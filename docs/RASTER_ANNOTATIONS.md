# Подготовка растровой разметки

`scripts/prepare_training_annotations.py` подготавливает черновики разметки
по `configs/training_samples.json`, проверяет подтверждённые полигоны и строит
маски сегментации в исходном разрешении. Предсказания модели при этом не используются.
Проверенные пары подключаются к `buildingcv.train` через загрузчик
`RasterMaskDataset`; настройка приведена ниже.

## Черновики

Из корня проекта:

```powershell
& .\.venv\Scripts\python.exe scripts/prepare_training_annotations.py init `
  --output output/training_annotations/2026-11-10-drafts
```

Папка должна быть новой: существующая разметка не перезаписывается.
Для семи новых планов черновики уже созданы в этом локальном каталоге.
Рядом находится `index.json` с назначением каждого изображения.
На этом этапе **масок ещё нет**. Пустой черновик не считается фоном.

Каждый `*.annotation.json` содержит неизменяемую ссылку на исходник,
SHA-256, размеры, состояние проверки и список объектов. Координаты задаются
в пикселях исходного изображения, до обрезки и изменения размера.
Поле `image` и `sample_id` необходимо сохранить из созданного черновика.

Пример отдельного объекта (координаты условные, не разметка реального плана):

```json
{
  "id": "wall-1",
  "class": "wall",
  "polygon": [[20, 20], [180, 20], [180, 32], [20, 32]]
}
```

Допустимы классы `wall`, `door`, `window`. Контур — простой полигон минимум
из трёх различных вершин; повторять первую вершину в конце не нужно.
Вершины должны находиться в пределах `0 <= x < width`, `0 <= y < height`.
Внутренние отверстия пока не поддерживаются: сложную стену с отверстиями
следует разбивать на несколько простых полигонов. Неизвестные поля объекта
отклоняются, чтобы неподдерживаемая геометрия не потерялась молча.

Оставлять `review.status: draft`, пока не просмотрено всё изображение.
Спорные участки записывать в `unresolved`, например:

```json
"unresolved": [{"bbox": [100, 100, 140, 140], "question": "Шахта или мебель?"}]
```

После проверки всех конструктивных объектов, фона и спорных участков:

```json
"review": {"status": "reviewed", "coverage": "full", "reviewer": "имя проверившего"},
"unresolved": []
```

Это подтверждение полного охвата, а не только правильности уже нарисованных
полигонов. Непомеченные пиксели станут `floor=0`, поэтому неполную разметку
подтверждать нельзя. Комнаты и соединения T/X размечаются отдельно по
[`GROUND_TRUTH.md`](GROUND_TRUTH.md); из этой маски их эталон не выводится.

## Маски и визуальная проверка

Черновую разметку можно посмотреть до подтверждения полного охвата:

```powershell
& .\.venv\Scripts\python.exe scripts/prepare_training_annotations.py preview `
  output/training_annotations/2026-11-10-drafts/colored-dimensions-eight-meter.annotation.json `
  --output output/training_annotations/first-plan-draft-preview.png
```

Команда сохраняет только диагностическое наложение с пометкой черновика;
вопросы из `unresolved` выделяются красными рамками. Она не создаёт маску,
не меняет состояние проверки и не перезаписывает существующий файл.
Участки вне нарисованных полигонов на таком просмотре не считаются
подтверждённым фоном.

Когда конкретный файл действительно проверен:

```powershell
& .\.venv\Scripts\python.exe scripts/prepare_training_annotations.py build `
  output/training_annotations/2026-11-10-drafts/colored-dimensions-eight-meter.annotation.json `
  --output output/training_annotations/reviewed-first-plan
```

Можно передать несколько файлов. Все они проверяются до записи результатов;
черновики, незакрытые вопросы, изменившийся исходник, самопересечения и
координаты вне изображения блокируют сборку. Версии с EXIF-поворотом нужно
заранее нормализовать и заново зарегистрировать.

Результат для каждого изображения:

- `*.mask.png` — одноканальная PNG с индексами `0/1/2/3`;
- `*.overlay.png` — разметка поверх исходника для визуальной проверки;
- `*.annotation.json` — копия проверенных полигонов;
- общий `masks.json` — происхождение, разделение, контрольные суммы и готовность.

Порядок наложения фиксирован: стены → двери → окна. Проёмы заменяют метку
стены независимо от порядка объектов в JSON. Обычные фоновые пиксели на
диагностическом изображении сохраняются без закрашивания.

Проверка семейств изображений остаётся отдельным этапом: пока
`group_review` в исходном реестре не равен `reviewed`, запись в `masks.json`
имеет `training_ready: false`, даже если геометрия уже проверена.
Одинаковые SHA-256 и одинаковые `group_id` в разных частях набора отклоняются.
Это не заменяет поиск похожих, обрезанных и перекодированных версий вручную.

Повторяемая проверка локальных изображений:

```powershell
& .\.venv\Scripts\python.exe scripts/audit_training_families.py `
  --output output/training_annotations/family-audit-next
```

Команда сравнивает новый реестр с `test/recognition_cases.json` и сохраняет
`report.json` и `contact-sheet.jpg` в новом каталоге. Одинаковые файлы и
заданные семейства в разных проверочных частях дают конфликт и код возврата 1.
Визуальные отпечатки учитывают повороты, изменение полей и сжатие; близкие
значения только предлагают пары для ручного просмотра. Они не гарантируют
нахождение всех родственных планов, не сравнивают с CubiCasa и не включают
`training_ready`. Даже без найденных пар нужно просмотреть общий лист
изображений и проверить происхождение базовых данных.

Изображения, рабочие JSON, маски и наложения остаются в игнорируемом `output/`.

## Подключение к обучению

В копии `configs/default.yaml` добавить в секцию `data`:

```yaml
data:
  data_dir: data/cubicasa5k
  include_cubicasa: true
  raster_manifest: output/training_annotations/reviewed-batch/masks.json
  raster_root: .
  image_size: [512, 512]
  num_workers: 0
  normalize: true
  letterbox: true
```

Остальные секции конфигурации сохраняются. Пути в конфигурации отсчитываются
от текущего каталога запуска; команды выполнять из корня проекта.
Пути масок и копий разметки отсчитываются от `masks.json`, пути исходных
изображений — от `raster_root`. В одном `masks.json` должны присутствовать
проверенные примеры обеих частей `train` и `val`. Итоговая часть `test` может
находиться в том же реестре, но обычное обучение её не загружает.

По умолчанию сохраняется исходный путь обучения на CubiCasa. С
`raster_manifest` проверенные растры добавляются в соответствующие части
исходного набора. Один проход включает каждый пример один раз; отдельного
увеличения частоты новых планов пока нет. Значение `include_cubicasa: false`
позволяет отдельно проверить растровый загрузчик; это не рекомендуемый режим
полноценного дообучения на четырёх планах.

Перед запуском модели:

```powershell
& .\.venv\Scripts\python.exe -m buildingcv.train `
  --config output/local-training.yaml --check-data
```

Проверка читает пары `train/val` и выводит количество примеров и пикселей
каждого класса после масштабирования. Модель и каталог обучения не создаются,
веса не скачиваются. `--limit-train` и `--limit-val` ограничивают проверку
для отладки; на смешанном наборе берутся первые примеры CubiCasa, поэтому
для проверки именно растров следует временно использовать
`include_cubicasa: false`. Наличие положительного числа примеров и проверенные
маски требуется в обеих частях даже при отладочных ограничениях.

Загрузчик проверяет контрольные суммы изображения, маски и копии разметки,
полный охват и имя проверившего, отсутствие нерешённых вопросов и готовность
семейства. Черновики отклоняются, а не пропускаются. Маска должна быть PNG
с индексами классов `0/1/2/3`, совпадать с исходным размером и содержать стены.
Метки неизвестных пикселей, например `255`, пока не поддерживаются.
Разделение семейств и одинаковых исходников проверяется по всему реестру,
включая метаданные `test`; это не проверяет сходство растров с CubiCasa.

Изображение и маска масштабируются совместно с сохранением пропорций при
`letterbox: true`; метки используют ближайшего соседа. Заполнение полей
соответствует существующему SVG-загрузчику: средний цвет изображения и класс
`floor`. В каталоге обучения сохраняется копия `raster_masks.json`, её
SHA-256 записывается в журнал. Возобновление с другим реестром блокируется;
для изменения состава данных нужен новый запуск.

Проверка на искусственных данных включает короткое обучение и возобновление
на CPU. Это проверяет подключение загрузчика, а не качество распознавания.
На семи новых планах обучение ещё не запускалось: их разметка остаётся черновой.
