# Experimental recognition V2

V2 теперь автоматически выбирает [полигональный экспорт](POLYGON_GEOMETRY.md)
для сложных форм. Вкладка «Геометрия экспорта» показывает его результат.
После выделения комнат V2 проверяет пропущенные двери по полотну и дуге
открывания: [OPENING_RECOVERY.md](OPENING_RECOVERY.md).
Осевые линии внутренних перегородок добавляются к графу границ комнат:
[INTERNAL_WALL_GRAPH.md](INTERNAL_WALL_GRAPH.md).

После этой итерации добавлена [проверка качества перед экспортом](QUALITY_GATE.md)
для V1 и V2. Исторические 8/10 ниже означают JSON-кандидаты; теперь gate
допускает 3 экспорта и блокирует 7 результатов.

## Запуск

V1 остаётся режимом по умолчанию. V2 включается явно:

```powershell
& .\.venv\Scripts\python.exe scripts/process_floorplan.py 'exmpls/Снимок экрана 2026-09-23 201535.png' --pipeline-v2
& .\.venv\Scripts\python.exe scripts/run_recognition_regression.py --pipeline-v2
```

В demo предусмотрен переключатель **«Улучшенное распознавание (экспериментальное)»**, по умолчанию выключенный.
API принимает необязательное multipart-поле `pipeline_v2=true`; без него используется V1.

Окружение и загрузка весов описаны в [REGRESSION_BASELINE.md](REGRESSION_BASELINE.md).

## Preprocessing

`scripts/preprocess_v2.py`:

- выделяет группы длинных структурных линий, включая диагональные;
- выбирает доминирующую область, оставляет запас и соседние структурные компоненты;
- при слабых или неоднозначных признаках сохраняет весь кадр;
- сохраняет плотно обрезанные контрастные нейтральные изображения без изменения;
- для цветных/малоконтрастных стен применяет проекцию по минимальному RGB-каналу и коррекцию контраста;
- сохраняет тонкие линии, мебель и текст: их семантику должен решать recognition, а не удаление всех тонких деталей.

Артефакты в `output/`:

```text
<stem>_preprocess.json
<stem>_preprocess_preview.png
<stem>_preprocessed.png
<stem>_grayscale.png
```

Метаданные содержат исходные размеры, ROI `[x1, y1, x2, y2]`, размеры crop, матрицы `source_to_crop` и `crop_to_source`, метод нормализации и причины отказа от crop.

`predict_raster.py --preprocess-meta ... --dual-pass` принимает исходное изображение и метаданные.
V2 выполняет выровненные проходы на исходном и normalized crop. Базовой остаётся нормализованная
маска; исходный проход добавляет только высокоуверенные пиксели с достаточной структурной
поддержкой. Если исходный проход почти не видит стен, его кандидаты игнорируются. Для идентичных
входов модель запускается один раз. Координаты стен и проёмов возвращаются в **исходный растр**,
используя фактические округлённые размеры letterbox по каждой оси. Классификация дверей/окон
выполняется на исходном изображении. Масштаб CLI остаётся количеством сантиметров на пиксель
исходного растра.

Дополнительные артефакты dual-pass:

```text
<stem>_inference.json
<stem>_segmentation_original.png
<stem>_segmentation_normalized.png
<stem>_segmentation_fused.png
```

Отчёт содержит долю расхождения проходов, число изменённых fusion-пикселей и число пикселей
каждого класса. Маски восстановлены в координаты исходного изображения.

## Room extraction

`scripts/extract_rooms_v2.py`:

1. Строит barrier из предсказанных стен и закрывает распознанные проёмы.
2. Извлекает исходные room candidates.
3. Ищет концы стен в skeleton и соосные разрывы между длинными участками маски.
4. Отбирает пары по направлению, локальной толщине, длине и отсутствию заполненной стены внутри gap.
5. Для широких разрывов требует дополнительный сигнал в исходном растре: непрерывную линию либо дверное полотно, привязанное к одному из стеновых торцов. Линия мебели в середине разрыва и проход без сигнала сохраняются открытыми.
6. Если rooms отсутствуют и почти вся структурная область соединена с outside,
   проверяет четыре стороны наружного bbox. Сильно фрагментированный, но
   подтверждённый контур временно замыкается только в barrier. Почти полный
   контур с одним проходом без полотна не замыкается этим fallback.
7. Выполняет conservative pass; при недостаточной замкнутости — relaxed pass.
   Только после принятого exterior fallback поиск чаще сканирует тонкие стены и
   допускает больший gap относительно локальной толщины. Для остальных планов
   прежние пороги сохраняются. Дубликаты с обратным порядком endpoints удаляются.
8. Принимает repair только если он улучшает число комнат или уменьшает утечку, сохраняет число ранее найденных комнат и как минимум 98% их суммарной площади.

Минимальная площадь кандидата зависит от структурного ROI и толщины стен. Дополнительно отбрасываются слишком тонкие области и невалидные полигоны.

Временные замыкания и inferred exterior envelope существуют в barrier и отдельной closure mask. Они **не добавляются в `walls` структурного JSON**. Room candidates, граничащие с замыканиями, помечаются `uncertain`. Сохраняются метрики каждого pass, side support наружного контура, причины принятия/отклонения repair и предупреждения.

Дополнительный артефакт: `<stem>_closures.png`. На room overlay временные замыкания показаны голубым, комнаты — пурпурным; `?` обозначает предполагаемую границу.

V2 выбирает полигональный адаптер для сложных форм, bbox — для прямоугольного эталона. Временное замыкание само по себе не становится физической стеной. Подтверждённая восстановленная дверь может служить опорой границы; остальные неподтверждённые участки блокируют экспорт. К графу границ добавляются осевые линии внутренних перегородок с подтверждением по исходной маске стен.

## Demo и API

Ответ API дополнен полями `pipeline` (`v1`/`v2`), `warnings` и `quality`. Проверка качества разделяет результаты на `good`, `review`, `invalid`; некорректный экспорт заблокирован. Это детерминированные проверки структуры, а не оценка accuracy модели.

Для V2 доступны дополнительные изображения: `preprocessing`, `normalized`,
`segmentation_original`, `segmentation_normalized`, `segmentation_fused`, `closures`,
`export`, `recovery`. Оригинал выбирается по UUID входного файла. В job-каталог копируются
отчёты preprocessing, inference, качества, геометрии и восстановления проёмов, а также
комнаты до и после восстановления.

Обнаруженная при проверке ошибка адаптера устранена: валидный `window_bindings.json` с `windows: []` больше не прерывает экспорт. Проект сохраняется с предупреждением и без добавления окон. Отсутствующий или некорректный массив `windows` остаётся ошибкой. Это разрешает отсутствие окон, но не означает, что распознавание всех окон было правильным.

## Ограничения и следующий шаг

- Два случая с размерными линиями по-прежнему дают 0 rooms: модель теряет существенные части наружного контура, включая угловые участки. Соосное замыкание не восстанавливает полностью отсутствующую структуру.
- Классификатор проёмов принимает некоторые окна, мебель и участки стен за двери. На цветном плане окна не распознаны, несмотря на восстановление стен.
- Inferred closures могут быть ошибочными; сложные случаи нужно проверять по overlay.
- Полигональный адаптер сохраняет сложные контуры, а граф внутренних стен переносит достаточно длинные и толстые ветви маски. Очень тонкие или неоднозначные перегородки могут быть пропущены; неподтверждённые границы и отверстия в форме остаются ограничениями.
- Gate проверяет overlap, ссылки и расстояния проёмов до стен, но не доказывает семантическую точность распознавания.

Следующие задачи — уточнение классификации существующих проёмов и полноты графа стен. V2 остаётся экспериментальным, с явным включением и предупреждениями. Таблица и проверки выше относятся к первой итерации V2; актуальные проверки описаны в связанных документах качества, геометрии, восстановления проёмов и внутренних стен.
