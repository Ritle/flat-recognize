# Полигональная геометрия экспорта

Итерация 2026-10-02 устраняет замену сложных комнат на bbox. Это первый
полигональный адаптер, **не полный граф всех распознанных стен**.
Нейросеть, классификация и выделение комнат не изменены.

## Включение

V1 сохраняет bbox-адаптер. В `--pipeline-v2` выбор автоматический: сложная форма
(площадь / envelope <0.9) или значительное наложение envelopes (≥20% меньшего)
включает полигональный режим. Чистый эталон сохраняет прежний экспорт.

```powershell
.\.venv\Scripts\python.exe scripts/process_floorplan.py path/to/plan.png --pipeline-v2
```

Проверка сохранённых rooms JSON без inference:

```powershell
.\.venv\Scripts\python.exe scripts/build_project_json.py `
  output/plan_rooms.json test/template.json --geometry-mode polygon `
  --output output/plan_project.json --geometry-report output/plan_geometry.json `
  --source-image path/to/plan.png --overlay output/plan_export_overlay.png
```

Режимы: `bbox` (default), `auto`, `polygon`. Прямой вызов builder создаёт
кандидат; перед использованием нужен `validate_recognition.py --geometry
output/plan_geometry.json`. Полный pipeline делает проверку автоматически.

## Построение

`polygon_geometry.py` смещает полигоны наружу на половину заданной толщины
стены в пикселях. Пересечения полос смещения делятся локальными биссектрисами.
Из сети границ строятся planar faces и назначаются комнатам по расстоянию
до исходного полигона. Исходные интерьеры сохраняются.

Контуры areas и segments получают общие коннекторы, включая T-junctions.
Наклонные и вогнутые границы сохраняются; общая стена не дублируется.
Положение осей приближённое, физический масштаб не калибруется.

Островки полос смещения вне исходных комнат исключаются с предупреждением.
Малые пустоты, созданные смещением (≤0.25 × квадрат радиуса, минимум 1 px²),
заполняются только если не заняты другой комнатой. Значительные пустоты,
исходные отверстия, несвязные комнаты и исходные наложения блокируются.

Segment создаётся только возле walls или известных doors/windows.
Участок временного замыкания без опоры на стену или распознанный проём
**не становится физической стеной**. Его граница получает узлы, но не segment;
gate выявляет незамкнутый area и блокирует экспорт.

Некорректные контуры walls/openings исправляются через buffer(0) только
в локальной проверке опоры; исходный JSON не меняется, отчёт требует проверки.
Если полигональную форму нельзя представить, сохраняется bbox-кандидат с
ошибкой. Возврат к bbox не разрешает скачивание.

## Проёмы и диагностика

`output/<stem>_geometry.json` хранит adapter, pixel_to_world, полигоны и
неподтверждённые участки. В полигональном режиме `add_openings.py` использует
точный transform вместо оценки по bbox. Для bbox сохранён прежний путь.

Дополнительная проверка идёт сразу после построения геометрии, до переноса
дверей/окон. Ошибка останавливает pipeline с кодом 2 и quality report.
Отчёт геометрии учитывается также в финальной проверке.

В demo добавлена вкладка «Геометрия экспорта»: синий — предложенные стены,
оранжевый — неподтверждённые участки. Job сохраняет `geometry.json`,
`geometry_candidate.json`, `export.png`. При блокировке счётчики проёмов
показывают распознанные двери/окна; число перенесённых остаётся в quality.metrics.

Прогон: `output/regression/geometry-v2-verified/report.md`.

| Пример | Адаптер | Status | Максимальное наложение areas |
|---|---|---|---:|
| clean-baseline, clean-variant | bbox | good | 0 |
| clean-diagonal | polygon | review | 0 (раньше 0.0796) |
| colored-walls | polygon | invalid: 5 неподтверждённых участков | 0 |
| balcony-text | polygon | invalid: 8 неподтверждённых участков | 0 |
| small-furnished | polygon | invalid: 10 неподтверждённых участков | 0 |
| complex-hatched | polygon | invalid: 2 неподтверждённых участка | 0 |
| open-zones | bbox diagnostic fallback | invalid: отверстие в геометрии | 1 |
| dimensions-png, dimensions-jpeg | не запускается | invalid: нет комнат | — |

Итог: **2 good / 1 review / 7 invalid**. На четырёх сложных планах устранены
наложения, но новые причины блокировки не обходятся. Диагональный план сохранил
наклонную границу и 6 rooms / 7 doors / 6 windows; количества не подтверждают accuracy.

Все 30 JSON сегментации/классификации/комнат совпали с предыдущим прогоном.
Эталон и clean-variant совпадают по проекту после нормализации случайных UUID:
5 комнат / 5 дверей / 6 окон. Прошёл 31 Python-тест; проверены переходы UI и HTTP-загрузки
эталона V1/V2, диагонального, цветного и размерного планов. Отчёт API:
`output/regression/demo-geometry-smoke/report.json`.

Остаются ложные/пропущенные проёмы и объединённые комнаты. Внутренние стены
одного связного помещения, не входящие в его внешнюю границу, пока не строятся
отдельным графом. Шумные контуры могут давать много коротких сегментов.
Нужны работа с проёмами, внутренними стенами и упрощением графа.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s test -p 'test_*.py' -v
node test/demo_quality_ui.test.cjs
```
