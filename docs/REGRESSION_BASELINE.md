# CPU baseline и регрессионный прогон

## Согласованные требования

- Текущая точка проверки результата — `demo/`.
- Эталон: `exmpls/Снимок экрана 2026-09-23 201535.png`.
- Ожидаемый итог эталона: **5 rooms / 5 doors / 6 windows**.
- Связное пространство без разделяющих стен — одна область; закрытые балконы и лоджии — отдельные области.
- Экспортируемая дверь должна иметь полотно.
- При отсутствии калибровки допустим приблизительный масштаб с предупреждением.
- Целевое поведение quality gate: `review` разрешает скачивание с предупреждениями; структурно некорректный JSON блокируется. Этот gate ещё не реализован в demo.
- `docs/AGENTS (1).md` применяется как инструкции для всего проекта.

## Подготовка на Windows

При установленном Python 3.11.9, из корня проекта:

```powershell
py -3.11 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -c configs/constraints-cpu.txt torch torchvision --index-url https://download.pytorch.org/whl/cpu
& .\.venv\Scripts\python.exe -m pip install -c configs/constraints-cpu.txt -e '.[serve]'
New-Item -ItemType Directory -Path weights -Force
curl.exe -fL -o weights/best.safetensors https://huggingface.co/Yytsi/floorplan-to-3d-walls/resolve/main/best.safetensors
curl.exe -fL -o weights/config.yaml https://huggingface.co/Yytsi/floorplan-to-3d-walls/resolve/main/config.yaml
```

Нативная библиотека Cairo требуется для SVG. Растровый pipeline импортирует CairoSVG только при фактическом SVG-рендеринге и работает без установки нативного Cairo.

## Повторяемый прогон

Манифест: `test/recognition_cases.json`. Изображения предоставляются отдельно в `exmpls/`.
Точные ожидаемые количества подтверждены только для `clean-baseline`; остальные случаи пока имеют категории и наблюдаемые результаты, без числовой ground truth.

```powershell
# Только эталон
& .\.venv\Scripts\python.exe scripts/run_recognition_regression.py --case clean-baseline

# Все 10 примеров
& .\.venv\Scripts\python.exe scripts/run_recognition_regression.py
```

По умолчанию каждый прогон создаёт новый каталог `output/regression/<UTC timestamp>/`.
`--output` задаёт другой новый каталог; существующий каталог отвергается.
`--case` можно повторить. `--threads` задаёт число потоков OMP/MKL, по умолчанию 4.

Прогон использует существующий `process_floorplan.py`, сохраняет объединённый stdout/stderr, копирует созданные или изменённые промежуточные JSON и изображения для каждого случая. `report.json` содержит версии пакетов, SHA-256 входов/весов/исходного кода, количества, этапы сбоев и время. `report.md` содержит сводную таблицу.

V1 пишет промежуточные файлы в общий `output/`: регрессионные прогоны нужно выполнять последовательно, без одновременной обработки тех же файлов через CLI. Сохранение артефактов учитывает изменения файлов, чтобы не включать старые результаты после сбоя.

Код возврата **0** означает, что все выбранные случаи завершились, прошли базовые проверки ссылок JSON и совпали с заданными ожиданиями. Код **1** означает сбой pipeline, нарушение проверяемого контракта, несовпадение заданных количеств или отсутствующий вход.

`pipeline_ok` означает техническое завершение с базовыми проверками JSON. Это **не** оценка правильности распознавания. Проверяются ссылки сегментов и проёмов, нулевая длина сегментов, границы областей, диапазон позиции проёма 0–100, ссылки материалов и наличие модели двери. Полная геометрическая валидация, overlap, физические размеры, door-leaf semantics и confidence остаются задачами следующего этапа.

## Измеренный результат V1

Полный прогон: `output/regression/v1-all/`. Первичный эталон до технических исправлений: `output/regression/baseline-initial/`.

|---|---:|---:|---:|---:|---|
| clean-baseline | 5 | 5 / 6 | 5 / 6 | 9.37 | Подтверждённые количества, контракт проходит |
| clean-variant | 5 | 5 / 6 | 5 / 6 | 9.55 | Pipeline завершён; ожидаемые количества отдельно не подтверждены |
| clean-diagonal | 5 | 9 / 6 | 9 / 6 | 9.47 | Ложные двери, диагональный контур заменяется прямоугольниками |
| dimensions-png | 0 | 12 / 2 | — | 9.29 | Разрывы barrier, соединение с outside |
| colored-walls | 0 | 0 / 0 | — | 9.57 | Модель вернула 0 wall polygons |
| balcony-text | 1 | 2 / 2 | 2 / 2 | 9.59 | Сохранилась только небольшая область; основные помещения потеряны |
| small-furnished | 0 | 9 / 1 | — | 10.07 | Разрывы barrier; небольшие компоненты также отфильтрованы |
| open-zones | 0 | 3 / 0 | — | 9.66 | Interior соединён с outside |

| complex-hatched | 7 | 16 / 1 | 16 / 1 | 10.32 | JSON сформирован; классификация проёмов и геометрия требуют проверки |

Итого: **5/10** случаев сформировали JSON с базовыми корректными ссылками; **5/10** остановились на `build_project_json.py: No rooms in source JSON` после результата `rooms=[]`. Это измерение технической успешности, не accuracy.

Все 10 случаев сохранили segmentation overlay, classified overlay, room overlay, barrier mask и промежуточные JSON завершённых этапов. Сопоставление диагностических изображений и JSON показало:

- Цветной план требует исправления входного представления/segmentation: room extraction не может восстановить отсутствующие стены.
- Планы с размерными линиями и открытыми зонами требуют восстановления topology; один связный outside-компонент захватывает внутренние помещения.
- На диагональном плане классификатор принимает некоторые участки стен и диагональное окно за двери.
- `balcony-text` демонстрирует ложный успех: одна небольшая область позволяет сформировать JSON, хотя большая часть квартиры потеряна.
- Даже при извлечении комнат текущий адаптер строит прямоугольники из bbox, что ограничивает L-shaped и диагональную геометрию.

Время включает запуск CLI и загрузку модели, а не только neural inference. Первый отдельный холодный запуск занял 21.38 с; последующий полный прогон — 9.29–10.32 с на случай. Эти измерения относятся к текущей машине и не являются SLA.

## Технические исправления этой итерации

Recognition-алгоритмы сохранены. Исправлены:

1. Отсутствующий `shapely` в зависимости `serve`.
2. Обязательный импорт нативного Cairo при растровом запуске — CairoSVG теперь импортируется внутри SVG-rendering функции.
3. `window.materials[*].itemUuid` после клонирования теперь равен UUID созданного окна. Первичный эталон имел 6 нарушений этого контракта.
4. Сохранение barrier mask через Pillow вместо `cv2.imwrite`, которое не сохраняло файл с кириллицей в имени на Windows.

После исправлений эталон сохранил количества 5/5/6, 18 segments, 14 connectors и прошёл базовые проверки итогового JSON. Все сформированные проекты полного прогона прошли эти же проверки.

## Следующая итерация

Начать с `preprocess_v2.py` и `--pipeline-v2`: нормализация цветных/серых стен, осторожный ROI с сохранением координат, диагностический preview. Затем `extract_rooms_v2.py`: замыкание подтверждённых проёмов и обоснованных разрывов для topology, с отдельной диагностикой inferred closures. Каждый этап проверять на эталоне и полном наборе; числовые ожидания сложных случаев подтвердить до объявления улучшения accuracy.
