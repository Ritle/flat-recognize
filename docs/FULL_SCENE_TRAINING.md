# Обучающие входы с мебелью и подписями

## Режимы SVG

Загрузчик поддерживает два явных режима входного изображения:

- `structural` — прежний режим по умолчанию: удаляются группы мебели,
  оборудования, размеров и подписей;
- `full` — исходная видимая сцена SVG с мебелью, подписями и размерными линиями.

Выбор задаётся в конфигурации обучения и оценки:

```yaml
data:
  svg_input_mode: full
  strict_svg: true
```

Размер, нормализация, изменение размера с сохранением пропорций и поля
сохраняются. Исходный SVG не переписывается, скрытые слои не включаются.
Маска по-прежнему строится из исходного SVG и содержит только четыре класса.
Мебель и подписи становятся дополнительными примерами фона, а не новым
классом. Если объект закрывает стену, структурная разметка стены сохраняется.
Полная сцена никогда не подменяет нерабочий пример соседним.

Это настройка подготовки данных для эксперимента. Растровый конвейер demo
и формат экспортируемого проекта не менялись. Вызовы отрисовки без указания
режима сохраняют структурный вариант.

## Строгий аудит перед обучением

Прежний аудит структурных входов не доказывает работоспособность полной
сцены: ранее удалённые SVG-элементы тоже должны успешно отрисоваться.
Настройте локальный Cairo по [data/README.md](../data/README.md), затем:

```powershell
& .\.venv\Scripts\python.exe scripts/audit_svg_dataset.py `
  --dataset data/cubicasa5k `
  --input-mode full --size 512 --workers 2 `
  --cache output/training_annotations/svg-full-scene-cache-512.json `
  --output output/training_annotations/full-scene-audit-next
```

Имена новых каталогов должны быть свободны. Кэш учитывает режим, SHA-256
SVG, код загрузки/отрисовки, размер и версии Cairo. Проверочная часть
обрабатывается первой. Ошибки записываются явно; код возврата `1`
означает найденные ошибки, отчёт при этом сохраняется.

Для подготовки отдельных списков без нерабочих обучающих примеров:

```powershell
& .\.venv\Scripts\python.exe scripts/prepare_svg_audit_splits.py `
  --audit output/training_annotations/svg-full-scene-audit-20261111/report.json `
  --source-splits output/training_annotations/cubicasa-deduplicated-20261110 `
  --output output/training_annotations/full-scene-splits-next
```

`provenance.json` сохраняет режим аудита. Списки `val/test` не сокращаются.
Ошибка в `val` останавливает подготовку; известная ошибка `test` остаётся
в списке и отмечается. Аудит `test` проверяет загрузку, не качество модели.

## Отдельная исходная оценка

Перед новым обучением исходные веса оцениваются на полной видимой сцене.
Используется прежняя маска и весь список из 400 проверочных SVG. Два новых
проверочных растра оцениваются отдельно; итоговый `test` не используется.

```powershell
& .\.venv\Scripts\python.exe -m buildingcv.eval_split `
  --config output/training_annotations/full-scene-baseline-20261111/config.yaml `
  --weights weights/best.safetensors --split val --source svg --device cpu `
  --output output/training_annotations/full-scene-baseline-next/val-svg.json
```

Оценка сохраняет режим в источнике данных. Сценарий сравнения отклоняет
прямое сравнение `full` и `structural` как результатов обучения на одинаковых
входах. Различие между этими режимами характеризует чувствительность одних
и тех же весов к содержимому изображения. Для проверки кандидата обе стороны
сравнения должны использовать одинаковый режим.

В отчёте оценки дополнительно сохраняется `confusion` по каждому классу:
`tp` — правильно найденные пиксели, `fp` — ложные, `fn` — пропущенные.
Пиксели `255` исключаются из всех трёх счётчиков. Это показатели пикселей,
а не число дверей, окон или стен. Они позволяют различать лишние предсказания
и пропуски при одинаковом IoU. Формула ошибки и расчёт IoU не менялись.

## Диагностика входов

В `output/training_annotations/full-scene-inputs-20261111/` сохранены три
реальных примера из разных базовых подгрупп: `colorful/1398`,
`high_quality/3909`, `high_quality_architectural/4967`.
Для каждого есть `structural.png`, `full.png`, `mask.png`,
`full-mask-overlay.png`, `comparison.png`. `manifest.json` содержит SHA-256
SVG и количество изменившихся пикселей. Маски двух режимов побайтово
совпадают; наложения проверены визуально.

Эти примеры показывают корректность подготовки данных. Улучшение модели
проверяется отдельным обучением и полным распознаванием, включая чистый
случай 5 комнат / 5 дверей / 6 окон, прежде чем применять новые веса.

## Обязательный контроль структурного входа

Для протокола полной сцены `compare_training_baseline.py` требует отчёт
кандидата на структурных входах через `--clean-control`. Исходный отчёт
загружается по ссылке `clean_control_baseline` из протокола. Отсутствие
контроля, другой режим изображения или веса другого кандидата останавливают
сравнение без сохранения решения. Снижение отдельных структурных классов
не может скрыться за улучшением среднего показателя полной сцены.

После оценки кандидата на полной сцене и новых растрах сохраните также
его структурный отчёт, используя прежнюю конфигурацию структурных входов:

```powershell
& .\.venv\Scripts\python.exe -m buildingcv.eval_split `
  --config output/training_annotations/finetune-ready-20261110/finetune-cpu.yaml `
  --weights output/training_annotations/pilot-full-scene-20261111/runs/<timestamp>/last.pt `
  --split val --source svg --device cpu `
  --output output/training_annotations/pilot-full-scene-20261111/evaluation/clean/val-svg.json
```

Замените `<timestamp>` именем каталога запуска. Итоговое сравнение:

```powershell
& .\.venv\Scripts\python.exe scripts/compare_training_baseline.py `
  --baseline output/training_annotations/full-scene-baseline-20261111 `
  --candidate output/training_annotations/pilot-full-scene-20261111/evaluation/full `
  --protocol output/training_annotations/pilot-full-scene-20261111/protocol.json `
  --clean-control output/training_annotations/pilot-full-scene-20261111/evaluation/clean/val-svg.json `
  --output output/training_annotations/pilot-full-scene-20261111/comparison.json
```

Вложенный `clean_control` сохраняет показатели и причины отказа контрольной
проверки. Для неё действует записанный до обучения допуск среднего IoU 0,005
и прежний допуск для каждого структурного класса. Прохождение всех проверок
даёт только допуск к проверке полного конвейера; файл рабочих весов не заменяется.
