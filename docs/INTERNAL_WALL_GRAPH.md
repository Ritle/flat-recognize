# Внутренние стены в графе проекта

V2 дополняет границы комнат осевыми линиями распознанных внутренних
перегородок. Ранее длинная стена внутри одного связного помещения могла
присутствовать в segmentation JSON, но отсутствовать в `segments`, потому
что адаптер строил только контуры комнат.

Этап реализован в `scripts/internal_wall_graph.py` и вызывается адаптером
через `--internal-walls`. Полный pipeline включает его только для
`--pipeline-v2`. Нейросеть, классификация, комнаты и формат целевого JSON
не изменены. На чистых планах без новых перегородок проект сохраняется
без изменений.

```powershell
& .\.venv\Scripts\python.exe scripts/process_floorplan.py path/to/plan.png --pipeline-v2
```

Перепроверка сохранённого структурного результата без inference:

```powershell
& .\.venv\Scripts\python.exe scripts/build_project_json.py `
  output/plan_rooms_recovered.json test/template.json --geometry-mode auto `
  --internal-walls --output output/plan_project.json `
  --geometry-report output/plan_geometry.json `
  --source-image path/to/plan.png --overlay output/plan_export_overlay.png
```

Прямой builder создаёт кандидат. Перед импортом требуется
`validate_recognition.py --rooms ... --project ... --geometry ...`;
полный pipeline выполняет проверку автоматически.

## Построение и ограничения

1. Маска строится из исходных wall polygons и известных проёмов около
   найденных помещений. Temporary closures в неё не добавляются.
2. CPU thinning превращает маску в skeleton. Рабочая сетка ограничена
   примерно 1024 пикселями по длинной стороне; mapping сохраняет исходные
   координаты.
3. Смежные пиксели junction объединяются в узел, ветви трассируются,
   осевые линии упрощаются. Уже представленные границами участки исключаются.
4. Короткие ветви и ветви без устойчивой толщины стены отбрасываются.
   Тонкая ветвь поперёк известного дверного проёма также может быть
   полотном и не экспортируется как перегородка.
5. Близкий конец соединяется с существующим сегментом только при опоре
   пути соединения на исходные walls/openings. Неподтверждённые временные
   замыкания и пути без опоры отбрасываются.
6. Ортогональная компонента должна находиться возле существующего графа
   границ либо соединяться с ним через другую принятую ось. Дальние
   изолированные компоненты сохраняются в diagnostics с причиной
   `isolated_wall_component`; типичный пример — контур кровати.
7. Общая сеть разбивается в пересечениях и T/X-соединениях. Обновляются
   adjacency, `left/right` и cycles комнат. Сохраняются существующие UUID
   несрезанных сегментов. Дубликаты и нулевые сегменты исключаются.

Это консервативное расширение графа, а не доказательство полноты или
семантической точности стен. Модель может принять мебель за достаточно
толстую стену. Очень тонкие стены, короткие простенки и неоднозначные
участки могут быть пропущены. Оси, концы и толщина приближённые; переменная
толщина исходного рисунка не переносится в физические размеры автоматически.
Плотные области и колонны требуют отдельной геометрической обработки.

Внутренняя перегородка не создаёт новое помещение: число и исходные полигоны
комнат сохраняются. Ошибочно объединённые комнаты должны исправляться
на этапе распознавания/топологии. Новые стены требуют `review`, если проект
в остальном корректен. Уже существующие ошибки продолжают давать `invalid`.

## Диагностика

Отчёт `<stem>_geometry.json` содержит `internal_wall_graph`:
метод, шаг raster, оценку толщины, число трасс, принятые линии,
отклонённые линии с причинами, добавленные сегменты и число разрезанных
исходных сегментов. Координаты линий относятся к исходному изображению.
В demo отчёт сохраняется в `geometry.json`, кандидат — в
`geometry_candidate.json`.

Вкладка «Геометрия экспорта»: синий — стены по контурам комнат,
бирюзовый — добавленные внутренние стены, оранжевый — неподтверждённые
границы. У заблокированного проекта эти материалы доступны для проверки;
скачивание JSON остаётся заблокированным.

## Проверка 2026-10-02

CPU-прогон всех 10 примеров: `output/regression/internal-wall-graph-v2/report.md`.

| Пример | Добавленных сегментов | Разрезанных исходных сегментов | Gate |
|---|---:|---:|---|
| clean-baseline, clean-variant | 0 | 0 | good |
| clean-diagonal | 0 | 0 | review |
| colored-walls | 8 | 1 | invalid |
| balcony-text | 5 | 0 | invalid |
| small-furnished | 0 | 0 | invalid |
| open-zones | 8 | 7 | invalid, diagnostic bbox fallback |
| complex-hatched | 1 | 0 | invalid |
| dimensions-png, dimensions-jpeg | этап не запускается | — | invalid, нет комнат |

Всего добавлено 22 сегмента. Их количество — наблюдение, не ground truth.
Результат gate: **2 good / 1 review / 7 invalid**. Внутренние стены не
устраняют оставшиеся неподтверждённые границы и отверстия в форме.

Эталон: **5 комнат / 5 дверей / 6 окон / 18 стен / 14 узлов**. Все три
допущенных проекта совпали с предыдущим прогоном после нормализации UUID.
Все 40 исходных промежуточных JSON (segmentation, classification, rooms,
rooms после восстановления дверей) совпали. В кандидатах проверены
геометрические пересечения: у пересекающихся сегментов есть общий узел,
наложений сегментов за его пределами нет.

Проходят 44 Python-теста и проверка JS demo. Новые тесты покрывают T/X-узлы,
примыкание к границе с обновлением area, диагонали, масштаб, пропущенные
проёмы без ложного соединения, исключение полотна и перенос двери на новую
внутреннюю стену с моделью полотна и корректными материалами.

HTTP-проверка demo: `output/regression/demo-internal-walls/report.json`.
Проверены эталон V1/V2 и три сложных плана V2: отчёт графа, картинки,
счётчики, оригинал, выдача корректного JSON и `409` для заблокированных.

## Проверка связности 2026-10-05

На `open-zones` изолированная ось по верхнему контуру кровати длиной 186.7 px
отклонена на расстоянии 94 px от графа комнат. Число добавленных сегментов
снизилось с 8 до 6. Статус остался `invalid`: фильтр стены не маскирует ошибки
room topology и bbox fallback.

Контрольные проверки сохраняют внутренние T/X junctions, диагональную стену,
частичную перегородку с дверью и стеновые участки по сторонам временного gap.
Короткая перегородка `complex-hatched` сохраняется.
