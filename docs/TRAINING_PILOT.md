# Ограниченное пробное дообучение

Пробный запуск проверяет смешанный путь обучения и влияние небольшого
числа новых планов. Он не заменяет полноценный эксперимент на разнообразной
разметке и не переключает веса сервиса.

## Подготовка и запуск

Из проверенного обучающего списка выбираются 32 SVG с фиксированным seed 42:
11 `colorful`, 11 `high_quality`, 10 `high_quality_architectural`.
Два новых обучающих растра сохраняются. Итого 34 обучающих примера.
Все 400 базовых и два новых проверочных примера остаются в `val`;
списки `val/test` копируются побайтово. Два отложенных пользователем плана
по-прежнему не участвуют. Итоговая часть `test` не используется.

Подготовка нового каталога из корня проекта:

```powershell
& .\.venv\Scripts\python.exe scripts/prepare_training_pilot.py `
  --config output/training_annotations/finetune-ready-20261110/finetune-cpu.yaml `
  --output output/training_annotations/pilot-next `
  --base-train-count 32 --seed 42
```

Скрипт создаёт `splits/`, `config.yaml`, `selection.json` с контрольными
суммами исходных списков и выбранных SVG. Проверяются пересечения частей
и допуск растровой разметки. Существующий каталог не перезаписывается.
Ограничение общего набора `--limit-train` не используется: оно могло бы
оставить только SVG, исключив новые растры из пробного обучения.

После настройки локального Cairo по [data/README.md](../data/README.md):

```powershell
$env:OMP_NUM_THREADS = '4'
$env:MKL_NUM_THREADS = '4'
& .\.venv\Scripts\python.exe -u -m buildingcv.train `
  --config output/training_annotations/pilot-next/config.yaml `
  --init-weights weights/best.safetensors
```

Одна эпоха, CPU, 512×512, пакет 2, скорость обучения `0.0001`.
`train.seed` задаёт начальное состояние Python, NumPy и PyTorch для нового
запуска. При `--resume` оно заново не задаётся; эта настройка не реализует
сохранение и восстановление всех состояний генераторов случайных чисел.
Кандидат сохраняется в `pilot-next/runs/<timestamp>/`, исходные веса
остаются по прежнему пути. В журнале выводится каждый шаг обучения
и каждые 20 пакетов проверки.

## Сравнение

После обучения повторите оценку отдельно для `svg` и `raster`, используя
сохранённый `last.pt`, полную часть `val` и новые файлы результата:

```powershell
& .\.venv\Scripts\python.exe -m buildingcv.eval_split `
  --config output/training_annotations/pilot-next/config.yaml `
  --weights output/training_annotations/pilot-next/runs/<timestamp>/last.pt `
  --split val --source raster --device cpu `
  --output output/training_annotations/pilot-next/evaluation/val-raster.json
```

Замените `<timestamp>` именем созданного каталога. Повторите с `--source svg`
и `evaluation/val-svg.json`. Для первого запуска протокол записан до обучения
в `output/training_annotations/pilot-20261111/protocol.json`:

- допустимое снижение базового среднего IoU — не более `0.005`;
- то же ограничение для каждого базового класса стен, дверей и окон;
- IoU новых стен не должен снижаться;
- IoU новых дверей и окон должен увеличиться.

Это предварительный отбор кандидата для проверки полного конвейера,
а не критерии готовности распознавания к эксплуатации.

```powershell
& .\.venv\Scripts\python.exe scripts/compare_training_baseline.py `
  --baseline output/training_annotations/baseline-20261111 `
  --candidate output/training_annotations/pilot-next/evaluation `
  --protocol output/training_annotations/pilot-20261111/protocol.json `
  --output output/training_annotations/pilot-next/comparison.json
```

Сравнение отклоняет изменённые проверочные исходники/маски, размеры входа,
нормализацию, неполные проходы и разные веса между частями одной оценки.
Средний результат не скрывает ухудшение отдельного класса. Прошедший отбор
кандидат требует проверки полного распознавания, чистого примера
5 комнат / 5 дверей / 6 окон и импорта проекта в приложение.
Код возврата `1` означает, что кандидат не прошёл отбор; JSON с причинами
при этом сохраняется. Код `0` означает допуск к проверке конвейера.

## Ограничение базовой части

`svg_render.render_input_png` удаляет мебель, размеры и подписи перед
отрисовкой SVG. Сильный результат на этой части характеризует очищенные
изображения. Новые растры содержат больше реальных помех и оцениваются
отдельно, только в подтверждённых областях частичной разметки.

Если смешанный пробный запуск не улучшит перенос, следующий эксперимент
должен расширять разнообразие обучающих входов. Один из общих путей —
отрисовка SVG с сохранением мебели и подписей при прежней структурной маске,
чтобы эти объекты были примерами фона. Нельзя подставлять исходный PNG
к маске SVG: их координатные пространства могут различаться. Изменение
подготовки входов требует отдельного эксперимента и новых исходных замеров.

Режим сохранения видимой мебели и подписей теперь реализован отдельно:
[FULL_SCENE_TRAINING.md](FULL_SCENE_TRAINING.md).

## Результат первого запуска — 11.11.2026

Запуск `pilot-20261111` завершил одну эпоху и 17 шагов оптимизатора на CPU.
Все 402 проверочных плана затем оценены отдельно по источникам:

| Проверочная часть | До | После |
|---|---:|---:|
| 400 базовых SVG, средний IoU | 0,983232 | 0,983066 |
| 2 новых растра, средний IoU | 0,270695 | 0,271608 |
| Новые стены, IoU | 0,152428 | 0,155181 |
| Новые двери, IoU | 0 | 0 |
| Новые окна, IoU | 0 | 0 |

Базовые показатели сохранились в пределах допуска. Кандидат отклонён,
поскольку двери и окна на новых проверочных примерах не улучшились.
`comparison.json` содержит две причины отклонения; CLI вернул ожидаемый код 1.
Исходные веса не изменились. Кандидат хранится отдельно, итоговая часть
`test` и конвейер экспорта для него не запускались. Небольшое изменение
на двух частичных масках не доказывает улучшения на других стилях.

Артефакты находятся в `output/training_annotations/pilot-20261111/`:
`selection.json`, `protocol.json`, `training-result.json`, `runs/`,
`evaluation/val-svg.json`, `evaluation/val-raster.json`, `comparison.json`.
