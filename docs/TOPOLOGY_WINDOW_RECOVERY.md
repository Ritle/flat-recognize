# Восстановление окон по топологии V2

На `open-zones` сегментация выделяет два верхних наружных окна, но первичный
фильтр отклоняет их из-за толщины полигона. Оба пропуска оставляют гостиную
соединённой с внешним фоном, поэтому `extract_rooms_v2` не создаёт комнату.
Простое повышение допустимой толщины нельзя использовать: на планах
`dimensions-png/jpeg` эти же отклонённые кандидаты разрушают уже найденные
помещения.

`recover_windows_topology_v2.py` запускается после классификации и до
`extract_rooms_v2` только в `--pipeline-v2`. Он рассматривает не более четырёх
кандидатов, отклонённых **только** по толщине. Кандидат должен быть вытянутым,
иметь ограниченную толщину, располагаться у стены и не дублировать известный
проём. Для каждого подмножества модуль повторно запускает `extract_rooms_v2`.
Окна принимаются только если одновременно:

- появилась новая комната и сохранено не менее 98% площади каждой исходной;
- доля внешнего фона внутри структуры упала минимум на 0,20 и стала меньше 0,30;
- суммарная внутренняя площадь выросла минимум на 10%.

Выбирается минимальное число кандидатов, а среди таких вариантов — наименьшая
доля внешнего фона. Восстановленные окна записываются в `windows/openings` с
`requires_review: true`. Новый модуль сохраняет JSON с решениями и пробами,
JSON классификации и overlay с голубыми контурами. Demo показывает этот overlay
отдельной вкладкой. Quality gate остаётся без послаблений.

На `open-zones` совместное добавление двух окон даёт 9 комнат вместо 8 и
снижает долю внешнего фона с 0,5298 до 0,1929. На overlay восстановилась
гостиная, но итоговый проект остаётся `invalid` из-за неверных привязок
проёмов. Сами два новых окна тоже пока имеют расстояние 36–42 см до
экспортных сегментов, что quality gate помечает как ошибку. На
`dimensions-png/jpeg` кандидаты не принимаются; остаётся 5 комнат.
Эталонный план остаётся 5 комнат / 5 дверей / 6 окон.

Риск ложного срабатывания остаётся для вытянутого объекта у внешней стены,
который одновременно закрывает крупную утечку маски. Автоматическое добавление
такого окна требует ручной проверки. Следующий шаг — проверить опору на стеновые
торцы и признаки дверного полотна, затем разметить эти окна в ground truth.

Полный CPU regression на 10 планах сохранён в
`output/regression/topology-window-full-v1/report.md`. Только `open-zones`
изменился: 8 → 9 комнат, 16 → 18 окон в конечном кандидате. Все остальные
комнаты, элементы и статусы совпали с предыдущим прогоном. Общий итог:
**2 good / 1 review / 7 invalid**; эталон 5/5/6 и интеграционный контракт
сохранены. Изменение не повышает статус `invalid` при неверной геометрии.
