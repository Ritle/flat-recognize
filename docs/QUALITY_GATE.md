# Проверка качества перед экспортом

Следующая итерация добавила [полигональный адаптер](POLYGON_GEOMETRY.md)
и проверку геометрии до переноса проёмов. Таблица ниже — исторический прогон
первого quality gate; актуальные причины блокировки приведены в новом документе.

Реализована 2026-10-02 для V1 и V2. Распознавание и контракт
`connectors / segments / areas / elements` не изменены; отчёт сохраняется отдельно.

| Status | Значение | Экспорт в demo |
|---|---|---|
| `good` | Проверки не выявили ошибок или причин для ручной проверки | Разрешён |
| `review` | Структура допустима, но есть сомнительные границы или проёмы | Разрешён с предупреждениями |
| `invalid` | Нет комнат или некорректна геометрия/ссылка | Заблокирован |

`good` не гарантирует совпадение с изображением. `quality` — оценка по правилам,
**не confidence модели и не accuracy**: 1.0 минус 0.08 за каждый различный код
предупреждения, минимум 0.1; при `invalid` — 0. Информационное сообщение
о приблизительном масштабе не снижает оценку и не меняет статус.

## Проверки

До построения проекта проверяются наличие комнат, конечные координаты,
невырожденные простые полигоны и наложения. После построения проверяются:

- уникальные непустые UUID в коллекциях;
- ссылки стен на узлы, ненулевая длина, положительные толщина и высота;
- соответствие adjacency реальным стенам;
- замкнутость areas существующими segments и валидность полигонов;
- сохранение числа распознанных комнат;
- существующая стена проёма и положение в диапазоне 0–100%;
- положительные размеры, material itemUuid, модель дверного полотна;
- число перенесённых проёмов и диагностических привязок;
- расстояние распознанного проёма до привязанной стены.

Наложение ≥20% площади меньшей комнаты — ошибка; 5–20% — предупреждение.
Касание допускается. Исходные полигоны и areas проверяются отдельно:
прямоугольный адаптер может создать наложения для раздельных исходных комнат.
Пороги — эвристики, не строительные нормативы.

Расстояние до стены больше `max(20 см, 1.5 × толщина стены)` — предупреждение.
Существующий этап привязки предупреждает при расстоянии >50 см, сохраняя привязку;
несовпадение числа проёмов переводит результат в `review`. Выход ширины
за конец сегмента более чем на 5 см, неуверенные замыкания и доля внешнего
фона ≥0.25 также требуют проверки.

## CLI

`process_floorplan.py` автоматически проверяет оба режима. Для
`--output path/project.json` отчёт — `path/project.quality.json`;
без output — `output/<stem>_final.quality.json`. Расстояния проёмов сохраняются
в `output/<stem>_opening_bindings.json`. Прежний `window_bindings` не изменён.

При `invalid` код завершения **2**. Если некорректны исходные комнаты,
построение не запускается. Если ошибка найдена в готовом проекте, JSON остаётся
диагностическим кандидатом на диске. Ранняя остановка повторного запуска
не удаляет существовавший output. Наличие файла не означает разрешение
экспорта: проверяйте код завершения и отчёт текущего запуска.

```powershell
.\.venv\Scripts\python.exe scripts/validate_recognition.py `
  --rooms output/plan_rooms.json --project output/plan_final.json `
  --bindings output/plan_opening_bindings.json --output output/plan_quality.json
```

## Demo и API

Завершённая проверка возвращает HTTP 200, включая `invalid`: `ok` означает
разрешение экспорта. Добавлены `quality`, `quality_url`; `warnings` сохранён.
При `invalid` ссылки `download_url` и `json_url` равны `null`.
Внутренний сбой pipeline по-прежнему возвращает HTTP 500.

Исходник и созданные diagnostic images доступны при блокировке. Job сохраняет
`quality.json`, `rooms.json`, при наличии — `opening_bindings.json` и
`preprocess.json`. Отчёт: `GET /api/jobs/<job-id>/quality`.

Прямые `/download` и `/json` для `invalid` возвращают HTTP **409**. Jobs без
отчёта также нельзя скачать: обработайте старое изображение повторно.
UI скрывает скачивание, JSON preview и копирование при блокировке и очищает
данные предыдущего успешного результата.

## Проверки на примерах

Полный V2-прогон: `output/regression/quality-v2/report.md`.

| Пример | Status | Причина |
|---|---|---|
| clean-baseline | good | Сохранены 5 комнат / 5 дверей / 6 окон |
| clean-variant | good | Проверки пройдены |
| clean-diagonal | review | Утечка, небольшое наложение, удалённый проём |
| dimensions-png, dimensions-jpeg | invalid | Нет комнат |
| colored-walls, balcony-text, small-furnished, open-zones, complex-hatched | invalid | Значительное наложение areas |

V2 формирует 8 JSON-кандидатов из 10. Допустимы 3 экспорта: 2 `good`, 1 `review`;
7 блокируются. Это выявленные ограничения, не улучшение accuracy. Геометрии
нужен отказ от bbox: улучшение inference само по себе не исправит эти наложения.

21 Python-тест покрывает прежние этапы, испорченные контуры/ссылки, наложения,
предупреждения и блокировку API. Реальная HTTP-проверка пяти загрузок проверяет
эталон V1/V2 (`good`), диагональный план (`review`), наложения и отсутствие
комнат (`invalid`), изображения, JSON и скачивание. Отчёт:
`output/regression/demo-quality-smoke/report.json`.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s test -p 'test_*.py' -v
node test/demo_quality_ui.test.cjs
.\.venv\Scripts\python.exe scripts/run_recognition_regression.py --pipeline-v2
```

Runner архивирует quality report, различает `quality_invalid` и обычный сбой.
Ненулевой код полного прогона ожидаем, пока набор включает некорректные планы.

Дополнительный тест JS выполняет реальный script из demo с минимальным DOM:
переход `good → invalid → review` очищает старый JSON и ссылку, не запрашивает
заблокированный JSON и восстанавливает экспорт при `review`. Браузерная
загрузка не проверена: расширению Chrome не предоставлен доступ к локальным
файлам; загрузки и скачивание проверены через HTTP API.
