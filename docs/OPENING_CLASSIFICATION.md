# Классификация существующих проёмов

`scripts/classify_openings.py` классифицирует opening-полигоны, уже найденные
segmentation. Этот этап не создаёт новые проёмы и не меняет wall mask.

Прежний критерий считал дверью любую подходящую перпендикулярную Hough-линию
возле угла opening bbox. На сложных планах такими линиями становились рамы окон,
края ванны, шкафов и мебели.

Текущая физическая дверь требует общего evidence из
`scripts/door_leaf_evidence.py`:

1. полотно сопоставимо с шириной проёма;
2. петля привязана к одному из стеновых торцов;
3. полотно проходит по свободному пространству, а не по широкой стене;
4. с обеих сторон проёма подтверждены стеновые косяки;
5. вокруг той же петли найдена согласованная дуга открывания.

Для model-source `door` действует ограниченный fallback без дуги: нужны два косяка,
диагональное полотно с углом 25–75° или 105–145° и свободный конец полотна. Такие
двери получают метод `source_door_two_jamb_diagonal_leaf`, поле
`requires_review: true` и предупреждение quality gate. Перпендикулярная линия без
дуги остаётся окном: так рамы и мебель не получают упрощённый путь подтверждения.

Если это evidence отсутствует, существующая бинарная схема сохраняет opening
как окно. В `classification` записываются method, подтверждение, исходный
semantic class и подробности полотна/дуги. Это консервативное решение повышает
precision дверей, но может превратить дверь со слабой или стёртой дугой в окно.
Такие false negative должны измеряться по ground truth до расширения recovery.

Старый `classify_opening()` оставлен как локальный сигнал для topology repair:
перпендикулярная линия сама по себе может помочь временно закрыть разрыв, но не
создаёт физическую дверь.

## Regression 2026-10-05

Полный CPU-прогон V2 сохранил clean результаты и статусы quality gate:

| Case | Было D/W | Стало D/W |
|---|---:|---:|
| clean-baseline | 5/6 | 5/6 |
| clean-variant | 5/6 | 5/6 |
| clean-diagonal | 7/6 | 7/6 |
| dimensions-png/jpeg | 15/0 | 5/10 |
| colored-walls | 8/0 | 0/8 |
| balcony-text | 6/2 | 0/8 |
| small-furnished | 9/1 | 2/8 |
| open-zones | 18/1 | 1/18 |
| complex-hatched | 16/1 | 9/8 |

Clean baseline также прошёл подтверждённый count ground truth: 5 rooms, 5 doors,
6 windows. Сложные counts остаются наблюдениями до пространственной разметки;
уменьшение числа дверей само по себе не считается ростом accuracy.

Room extraction использует объединение дверей и окон как barrier, поэтому одно
только изменение типа не исправляет topology. Для этого отдельно нужны отсев
ложных opening-полигонов и очистка structural wall mask.

## Regression 2026-10-06

После проверки двух косяков и ограниченного fallback clean baseline сохранил
**5 doors / 6 windows**. Визуальная проверка `open-zones` показала конкретное
улучшение: ложная дверь на кухонной плите удалена, двери спальни и санузла
подтверждены по диагональному полотну и двум косякам.

| Case | До D/W | После D/W | Наблюдение |
|---|---:|---:|---|
| clean-baseline | 5/6 | 5/6 | подтверждённый baseline сохранён |
| clean-variant | 5/6 | 5/6 | без изменения |
| clean-diagonal | 7/6 | 6/7 | удалён кандидат без второго косяка |
| dimensions-png/jpeg | 5/10 | 0/15 | прежние зелёные кандидаты были размерной графикой/мебелью |
| colored-walls | 0/8 | 0/8 | реальная дверь имеет только один распознанный косяк |
| balcony-text | 0/8 | 0/8 | диагональ шкафа не прошла проверку двух косяков |
| small-furnished | 2/8 | 0/10 | прежние кандидаты находились на мебели |
| open-zones | 1/18 | 2/17 | удалена плита, добавлены две реальные двери |
| complex-hatched | 9/8 | 9/8 | число прежнее; один слабый кандидат заменён дверью с двумя косяками |

Кроме clean baseline эти counts остаются наблюдениями до геометрической разметки.
Нулевое число дверей на сложном плане означает недостаточную segmentation проёмов,
а не доказанное отсутствие дверей.

## Уточнение 2026-10-07: оконные кандидаты на изолированных линиях

Классификатор отклоняет model-source `window`, если кандидат не имеет двух
подтверждённых стеновых косяков хотя бы на одном конце и лежит на достаточно
крупной изолированной компоненте маски стен, существенно более тонкой, чем
основные стены. Это защита от мебели и графики, ошибочно размеченных моделью
одновременно как стена и окно. Отклонённые кандидаты остаются в
`rejected_openings`, отмечаются оранжевым на overlay и вызывают предупреждение
в диагностике комнат. Подтверждённые косяками и model-source `door` не
затрагиваются.

Полный CPU-regression на десяти примерах изменил только `open-zones`: два окна
на плите/мебели отклонены (17 → 15), а адаптер комнат смог использовать
полигоны без перекрытия. Число комнат осталось 8; quality gate сохранил
`invalid`, поскольку остаются шесть неподтверждённых сегментов и незамкнутые
границы. Clean baseline сохранил 5 rooms / 5 doors / 6 windows и `good`.
Этот фильтр повышает precision, но несёт риск отбросить настоящее окно на
тонкой отдельной стене; такие случаи требуют проверки по ground truth.
